# v0.5.1 Wrap-up — Design Spec

**Date:** 2026-09-04
**Author:** Claude (brainstorming session with LCUstinian)
**Target release:** v0.5.1
**Branch:** `main` (no worktree isolation)
**Scope:** Doc fixes + test coverage gaps + tag — **no business-logic changes**

---

## 1. Background

v0.5.1 has been shipping incrementally to `main` since commit
`ca259d55ce` (2026-09-03, `feat(v0.5.1): output/file/UX hardening +
short-flag overhaul`). The `[Unreleased]` block of `CHANGELOG.md`
already documents the major items: hard-exit data-loss fix, daily-
bucketed result directories, HH-MM-SS filename stamp, `fgqm_` prefix
on all result files, short-flag overhaul, `time/tzdata` embed, and
the `applySchedule` test push.

The `fgqm_alive.txt` (dedup'd alive-host list, see
`internal/output/output.go:396`) was added in the same commit batch
but was **not documented** in either the README output-files section
or the CHANGELOG `[Unreleased]` block, and **no end-to-end test
pins the alive-path's full filename contract** (date bucket + HH-MM-SS
stamp). A user review on 2026-09-04 caught that the README describes
`fgqm_alive.txt` (bare name, no timestamp) — making it look like the
file has no date, when in reality it lands at
`runs/<project|default>/<YYYY-MM-DD>/fgqm_alive_<HH-MM-SS>.txt`.

This spec is the minimal-blast-radius wrap-up that closes those
documentation / test-coverage gaps and tags the result as `v0.5.1`.

## 2. Goals & non-goals

### Goals
1. **Fix the README description** so the alive sink's filename is
   documented as the same `_<HH-MM-SS>`-stamped format as the other
   timestamped sinks (consistency with `fgqm_result_*`, `fgqm_rdp_*`).
2. **Pin the alive-path contract** with two end-to-end tests in
   `cmd/cmd_test.go` that assert the full resolved path (date bucket
   + HH-MM-SS stamp) for both project and ephemeral modes.
3. **Pin the alive-write behavior** with four tests in
   `internal/output/output_test.go` covering dedup, empty-host
   no-op, concurrent write safety, and nil-when-disabled safety.
4. **Add a CHANGELOG `[Unreleased]` entry** that records the alive
   sink as an `Added` item (so the README change has a corresponding
   changelog reference for the doc-correctness audit trail).
5. **Author a v0.5.1 verification report** mirroring the structure
   of `docs/verification/v0.5/verification.md`.
6. **Tag `v0.5.1`** on `main` once all five artifacts above are
   committed and the test suite passes locally.

### Non-goals (explicit out-of-scope)
- ❌ Business-logic changes — `output.go`, `scan.go`, and friends stay
  exactly as they are now. The code already does the right thing.
- ❌ A2 coverage-floor bump (60% → 65%) — `CHANGELOG.md` already
  documents the deferral to v0.6 because 30+ adapted plugins sit at
  0% coverage (need fake-server infrastructure = v0.7 work).
- ❌ New CLI flags for alive format (`--alive-format {txt,json,csv}`)
  — that's a feature, not wrap-up.
- ❌ Comment header on the alive file (`# fg-qimen alive list ...`)
  — would be a backwards-incompatible change for `nmap -iL` users;
  out of scope for "minimal wrap-up".
- ❌ Worktree isolation — actions are all doc/test/tag; the diff is
  reviewable in one commit, no need for the `worktree` ceremony.
- ❌ Distributed scan / web fingerprint / plugin hot-load — those
  belong to v0.6/v0.7/v0.8 (see roadmap observation #10791).

## 3. The five artifacts

### 3.1 README.md output-files section correction

**File:** `README.md` line 163 (the "Output files" list under
"### Workspace project layout" or equivalent).

**Current (wrong):**
```markdown
- `fgqm_alive.txt` — one IP per line (dedup'd host list for `nmap -iL` /
  `masscan --targets` / `curl` loops)
```

**Replace with:**
```markdown
- `fgqm_alive_HH-MM-SS.txt` — one IP per line (dedup'd host list for
  `nmap -iL` / `masscan --targets` / `curl` loops). Same daily bucket
  (`YYYY-MM-DD/`) + `HH-MM-SS` filename stamp as the other timestamped
  sinks (`fgqm_result_*`, `fgqm_rdp_*`).
```

**Why:** The bare `fgqm_alive.txt` reads as "no date", but the file
actually lands at
`runs/default/<YYYY-MM-DD>/fgqm_alive_<HH-MM-SS>.txt`. The README
description must mirror the other timestamped sinks so operators can
predict where the file lands.

### 3.3 Four `WriteResult` alive-behavior tests

**File:** `internal/output/output_test.go` — append to the existing
test file (uses the existing helper functions for opening a temp
`output.Output` against a `t.TempDir()` path).

```go
// TestWriteResult_AliveSinkDedup: the same host pushed N times yields
// exactly one line in the alive file. Pinned to defend the dedup-map
// contract under aliveMu.
func TestWriteResult_AliveSinkDedup(t *testing.T) {
    dir := t.TempDir()
    alivePath := filepath.Join(dir, "alive.txt")
    out, err := output.OpenOutput(output.OutputConfig{
        ResultTXTPath:   filepath.Join(dir, "r.txt"),
        ResultJSONPath:  filepath.Join(dir, "r.json"),
        CredsPath:       filepath.Join(dir, "c.txt"),
        RDPJSONPath:      filepath.Join(dir, "rj.json"),
        RDPTXTPath:      filepath.Join(dir, "rt.txt"),
        ResultAlivePath: alivePath,
    })
    if err != nil { t.Fatalf("OpenOutput: %v", err) }
    defer out.Close()

    for i := 0; i < 5; i++ {
        if err := out.WriteResult(&types.Result{Host: "10.0.0.1", Port: 22, Service: "ssh"}); err != nil {
            t.Fatalf("WriteResult: %v", err)
        }
    }
    if err := out.Close(); err != nil { t.Fatalf("Close: %v", err) }

    body, err := os.ReadFile(alivePath)
    if err != nil { t.Fatalf("ReadFile: %v", err) }
    lines := strings.Split(strings.TrimRight(string(body), "\n"), "\n")
    if len(lines) != 1 || lines[0] != "10.0.0.1" {
        t.Errorf("alive file = %q, want single line %q", body, "10.0.0.1")
    }
}

// TestWriteResult_AliveSinkEmptyHost: r.Host == "" produces no
// write — defensive against stray blank lines that would break
// `nmap -iL` (which treats blank lines as syntax errors in some
// versions).
func TestWriteResult_AliveSinkEmptyHost(t *testing.T) {
    dir := t.TempDir()
    alivePath := filepath.Join(dir, "alive.txt")
    out, _ := output.OpenOutput(output.OutputConfig{
        ResultTXTPath:   filepath.Join(dir, "r.txt"),
        ResultJSONPath:  filepath.Join(dir, "r.json"),
        CredsPath:       filepath.Join(dir, "c.txt"),
        RDPJSONPath:      filepath.Join(dir, "rj.json"),
        RDPTXTPath:      filepath.Join(dir, "rt.txt"),
        ResultAlivePath: alivePath,
    })
    defer out.Close()

    if err := out.WriteResult(&types.Result{Host: "", Port: 22, Service: "ssh"}); err != nil {
        t.Fatalf("WriteResult: %v", err)
    }
    if err := out.Close(); err != nil { t.Fatalf("Close: %v", err) }

    body, _ := os.ReadFile(alivePath)
    if len(strings.TrimSpace(string(body))) != 0 {
        t.Errorf("alive file = %q, want empty", body)
    }
}

// TestWriteResult_AliveSinkConcurrent: 100 goroutines pushing the
// same host → file contains exactly one line (aliveMu + dedup-map
// thread-safety contract).
func TestWriteResult_AliveSinkConcurrent(t *testing.T) {
    dir := t.TempDir()
    alivePath := filepath.Join(dir, "alive.txt")
    out, _ := output.OpenOutput(output.OutputConfig{
        ResultTXTPath:   filepath.Join(dir, "r.txt"),
        ResultJSONPath:  filepath.Join(dir, "r.json"),
        CredsPath:       filepath.Join(dir, "c.txt"),
        RDPJSONPath:      filepath.Join(dir, "rj.json"),
        RDPTXTPath:      filepath.Join(dir, "rt.txt"),
        ResultAlivePath: alivePath,
    })
    defer out.Close()

    var wg sync.WaitGroup
    for i := 0; i < 100; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            _ = out.WriteResult(&types.Result{Host: "10.0.0.1", Port: 22})
        }()
    }
    wg.Wait()
    if err := out.Close(); err != nil { t.Fatalf("Close: %v", err) }

    body, _ := os.ReadFile(alivePath)
    lines := strings.Split(strings.TrimRight(string(body), "\n"), "\n")
    if len(lines) != 1 || lines[0] != "10.0.0.1" {
        t.Errorf("alive file under concurrency = %q, want single line %q", body, "10.0.0.1")
    }
}

// TestWriteResult_AliveSinkNilWhenDisabled: ResultAlivePath == ""
// must leave out.alive nil so WriteResult safely no-ops the
// alive-sink branch (no panic, no file creation).
func TestWriteResult_AliveSinkNilWhenDisabled(t *testing.T) {
    dir := t.TempDir()
    out, err := output.OpenOutput(output.OutputConfig{
        ResultTXTPath:   filepath.Join(dir, "r.txt"),
        ResultJSONPath:  filepath.Join(dir, "r.json"),
        CredsPath:       filepath.Join(dir, "c.txt"),
        RDPJSONPath:      filepath.Join(dir, "rj.json"),
        RDPTXTPath:      filepath.Join(dir, "rt.txt"),
        ResultAlivePath: "", // disabled
    })
    if err != nil { t.Fatalf("OpenOutput: %v", err) }
    defer out.Close()

    // Should not panic; should not create any alive file in dir.
    if err := out.WriteResult(&types.Result{Host: "10.0.0.1", Port: 22}); err != nil {
        t.Fatalf("WriteResult: %v", err)
    }
    if err := out.Close(); err != nil { t.Fatalf("Close: %v", err) }

    matches, _ := filepath.Glob(filepath.Join(dir, "alive*"))
    if len(matches) != 0 {
        t.Errorf("disabled alive sink created files: %v", matches)
    }
}
```

**Why:** `output.go:396-403` has four observable behaviors (single
host dedup, empty-host no-op, concurrent write safety, nil-when-
disabled safety). None of them are pinned by tests today — the only
alive-related test is the static-stamp test in
`cmd/cmd_test.go:306`. A regression in any of these four behaviors
would land silently without these tests.
